# OBJ 모델 로딩

캐릭터와 행성은 프로젝트의 `ObjModelLoader`로 읽습니다. 외부 모델 라이브러리의 설치, 다운로드, 헤더·라이브러리 경로 설정은 필요하지 않습니다. 기존 Direct3D와 Windows SDK의 빌드 환경은 유지합니다.

## 파일 배치

저장소 기준으로 다음 파일을 함께 전달합니다.

```text
Project/assets/model/
├─ character/
│  ├─ Meshy_AI_01_Arc_Sentinel_1005152429_texture.obj
│  ├─ Meshy_AI_01_Arc_Sentinel_1005152429_texture.mtl
│  └─ Meshy_AI_01_Arc_Sentinel_1005152429_texture.png
└─ planet/
   ├─ future_ruins_realistic.obj
   └─ future_ruins_realistic.mtl
```

OBJ의 `mtllib`이 MTL을 가리키고, MTL의 이미지 경로가 실제 파일을 가리켜야 합니다. 모델을 다른 파일로 교체할 때는 OBJ, MTL, 텍스처를 함께 갱신합니다. 확장자를 바꾸는 대신 모델 제작 도구에서 OBJ로 내보내야 합니다.

Client의 빌드 후 대상이 OBJ·MTL·이미지를 실행 파일 옆 `assets/model`에 복사합니다. Server는 지형 조회에 필요한 행성 OBJ만 복사합니다. 다른 PC에서 Git LFS로 관리하는 모델을 받았다면 실제 파일이 내려왔는지 확인하세요.

## 기존 구조와 연결

- `Engine`: 에셋 경로와 모델 배치 변환을 지정합니다.
- `ResourceManager → ObjModelLoader`: CPU 데이터인 `ModelData`를 생성하고 GPU 업로드 전까지 캐시합니다.
- `Model → LegacyScene → GRenderer`: 기존 방식으로 GPU 버퍼를 만들고 표시합니다.
- `Shared::PlanetSurface → TerrainSampler`: 행성 OBJ의 접지 삼각형과 지면 높이를 클라이언트·서버에서 공유합니다.

OBJ의 오브젝트와 재질 구분을 기존 `ModelData`의 노드·메시·재질로 옮깁니다. 모델 파일의 수명이나 외부 라이브러리 객체가 장면에 남지 않습니다. 플레이어·원격 플레이어·NPC는 같은 캐릭터 데이터와 기존 이동·회전 코드를 사용합니다.

위치와 법선의 Z, 삼각형의 면 순서를 반전해 DirectX 좌수계로 변환합니다. UV의 V와 노멀맵의 녹색 채널도 로딩 단계에서 한 번 보정합니다. 셰이더에서 다시 뒤집지 않습니다. 캐릭터의 높이·중심·정면 보정은 `Model::Initialize`의 캐릭터 표시 변환에서 담당합니다. 현재 캐릭터 원본은 Y 위쪽으로 내보냈으며, Y축으로 180도 회전해 게임의 +Z 정면에 맞춥니다. 행성에는 이 캐릭터 표시 변환을 적용하지 않습니다.

길이가 0인 법선은 유효한 면의 형상으로 복구하며, 면적이 0인 삼각형은 제외합니다. 잘못된 인덱스나 비유한 정점 값은 오류로 보고합니다. 원본에 없는 재질 표현이나 절차적 Blender 노드가 자동으로 텍스처로 변환되지는 않습니다.

## 모델 메모리 수명

`ObjModelLoader`는 객체·재질 부분을 완성할 때 검색용 해시를 해제하고 정점·인덱스 벡터의 여유 용량을 줄입니다. 원본 좌표·법선·UV 배열은 파싱이 끝난 뒤 해제합니다. 현재 행성 데이터 기준으로 메시 벡터의 여유 공간 약 **153.8 MiB**를 줄이는 변경이며, 실제 메모리 사용량을 측정한 수치는 아닙니다.

`GRenderer::CreateMesh`는 정점·인덱스를 하나의 `DEFAULT` 버퍼에 넣습니다. 임시 `UPLOAD` 버퍼는 해당 메시의 복사와 선택적 BLAS 생성이 GPU에서 끝날 때까지 보관한 뒤 해제합니다. 정점·인덱스 버퍼를 따로 만들 때 발생하던 리소스별 정렬 공간도 줄입니다.

`Engine`은 행성과 캐릭터의 `Model::Initialize`가 성공하면 `ResourceManager::ReleaseModel`을 호출합니다. CPU 메시와 디코딩된 텍스처 픽셀이 해제되며, 이전 CPU 모델 핸들과 `Get()` 포인터는 무효가 됩니다. 같은 파일을 다시 `LoadModel`로 요청하면 다시 읽습니다. `Model`이 보관한 노드 계층과 GPU 핸들은 유지되므로 플레이어·원격 플레이어·NPC의 `Instantiate`는 그대로 공유 자원을 사용합니다.

현재 행성의 정점·인덱스 실제 데이터는 약 **591.8 MiB**이며 렌더링에 필요한 GPU 사본은 유지됩니다. 외장 GPU에서는 `DEFAULT` 힙이 GPU 메모리를 사용하고, 내장 GPU의 공유 메모리 환경에서는 시스템 RAM을 함께 사용할 수 있습니다. 파일 파싱과 GPU 복사가 진행되는 동안의 임시 사용량은 남습니다.

## 범위

OBJ는 정적인 메시 형식입니다. 캐릭터의 이동·회전은 기존 게임 코드로 처리하지만 뼈·스킨 가중치·뼈 애니메이션을 OBJ에서 읽지는 않습니다. 향후 뼈 애니메이션을 적용하려면 별도의 데이터 형식과 스키닝 처리가 필요합니다.

행성의 크기·재질·접지 규칙은 `PLANET_MODEL.md`를 참고하세요. 이번 변경의 빌드와 실행 확인은 사용자가 진행합니다.
