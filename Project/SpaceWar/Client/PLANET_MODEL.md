# 접지 보정된 폐허 행성 맵

게임은 `Project/assets/model/planet/future_ruins_realistic.obj`와 같은 폴더의 `future_ruins_realistic.mtl`을 읽습니다. 수정된 맵은 미터 단위로 제작했으며, 행성 표면에 건물·도로·차량·엄폐물과 잔해를 접지했습니다. 이전 장식용 공중 파편과 Blender의 먼지 대기 구는 게임용 OBJ에서 제외했습니다. 충돌 검사용 메시도 화면에 표시할 맵 OBJ에 포함하지 않습니다.

## 좌표와 크기

- `Shared::kPlanetRadius`: **1,600m**, 게임의 행성 반지름을 유지합니다.
- `Shared::kPlanetModelReferenceRadius`: **1,600m**, 새 OBJ의 `Planet_Core` 평균 반경에 맞춥니다.
- `Engine`의 표시 배율: **1** (`kPlanetRadius / kPlanetModelReferenceRadius`).
- 행성 중심: **(0, -1600, 0)**. OBJ 자체의 중심은 **(0, 0, 0)**입니다.

이전 모델은 평균 반경 약 72.76인 행성 전체를 약 22배 확대했으므로 건물과 차량도 함께 커졌습니다. 새 모델은 행성 표면의 규모를 1,600m로 맞추고 FPS용 구조물은 사람에 맞는 크기로 재배치했습니다. 도로와 구조물을 여섯 정착지로 모아 배치했으며, 주 정착지는 게임의 **+Y 스폰 방향**에 있습니다. Blender의 **+Z 위쪽**이 OBJ의 **+Y 위쪽**으로 변환됩니다.

원본 지형의 미터 단위 기복은 확대하지 않았습니다. 지형 기준구만 1,600m에 맞추고, 건물 주변의 바닥·진입로·계단 연결과 도로 틈을 정리했습니다. 따라서 전체 행성 크기를 유지하면서 전장의 지형과 구조물은 사람 크기에 맞는 규모로 보입니다.

`ObjModelLoader`는 위치·법선의 Z와 면의 순서를 반전해 DirectX 좌수계로 변환합니다. `Shared::PlanetSurface`의 지면 조회도 같은 Z 반전을 적용합니다. 캐릭터와 행성 모두 OBJ를 사용하며, 캐릭터의 높이·중심·정면 방향 보정은 `Model::Initialize`의 캐릭터 표시 변환에서 적용합니다. 현재 캐릭터 OBJ는 Y 위쪽으로 내보냈으며 Y축으로 180도 회전해 게임의 +Z 정면에 맞춥니다. 캐릭터 높이 **2m**와 몸통 중심의 지면 오프셋 **1m**는 기존 설정을 유지합니다.

새 OBJ와 이전 기준 반경 72.762866을 섞으면 모델이 다시 약 22배 커집니다. 반대로 이전 OBJ와 새 기준 반경 1,600을 섞으면 지면이 행성 중심 쪽으로 들어갑니다. 클라이언트·서버 빌드와 맵 파일을 함께 갱신해야 합니다.

## 연결 구조

- `Engine`: 행성 파일 로드, 표시 배율 및 행성 중심 배치
- `ResourceManager → ObjModelLoader`: OBJ 메시, MTL 재질 및 외부 이미지 로드
- `Model → LegacyScene → GRenderer`: GPU 업로드 및 렌더링
- `Shared::PlanetSurface → TerrainSampler`: 같은 OBJ의 지면을 BVH로 보관하고 방향별 높이 조회
- `Planet::SurfaceHeight`: 플레이어의 스폰·착지·카메라 지면 보정
- `Server`: 같은 파일·반경·배율로 플레이어와 NPC의 지면 높이 계산

지면 조회는 `Planet_Core`, `Fragmented_Planet_Armor`와 이름에 `Asphalt`, `Sidewalk`, `Paving`, `Ramp`, `Subgrade`, `Approaches`, `Foundations`, `Curbs`, `Lane_Lines`, `Surface_Gravel`이 포함된 객체를 사용합니다. 새 지면 객체를 추가할 때 이 이름 규칙을 유지해야 합니다. 건물 지붕과 벽을 지면으로 읽으면 그 아래의 플레이어가 지붕 위로 밀려나므로 제외합니다.

현재 물리는 방향별 높이 하나를 쓰는 구면 지면 구조입니다. 이 경로는 지면 높이를 맞추며, **건물 벽·실내·교량 아래의 체적 충돌을 처리하는 기능은 아닙니다.** Blender에서 확인한 건물 출입과 이동 공간을 실제 게임 충돌로 사용하려면 별도 충돌 처리가 필요합니다.

## 지면 메모리

OBJ 파싱 중에는 전역 정점 인덱스와 음수 인덱스를 처리하기 위해 모든 위치를 읽습니다. 파싱이 끝나면 접지 삼각형이 참조하는 위치만 남기고 삼각형 인덱스를 다시 연결합니다. 좌표 값과 접지 삼각형은 그대로 유지하며, 렌더링용 메시에는 영향을 주지 않습니다.

위치·삼각형 벡터의 여유 용량을 줄이고, BVH는 기존 절반 분할과 리프당 최대 8개 삼각형에 맞춰 실제 필요한 노드 수만 예약합니다. 이전 기록의 접지 삼각형 **2,193,369개** 기준으로 BVH 여유 공간 약 **14.5 MiB**가 줄어듭니다. 사용하지 않는 위치 제거에 따른 절감량은 모델 구성에 따라 달라집니다. 이 처리는 클라이언트와 서버가 공유합니다.

렌더링 메시의 GPU 업로드가 끝나면 CPU 모델 캐시를 해제합니다. 정적 GPU 버퍼와 업로드 버퍼의 수명은 `OBJ_MODEL.md`를 참고하세요.

## 재질

새 MTL은 **18개 사용 재질**의 근사 기본 색상(`Kd`), 거칠기(`Pr`), 금속성(`Pm`)과 발광(`Ke`)을 제공합니다. 게임 로더는 이 값을 기본 색상·거칠기·금속성·발광 값으로 읽습니다. 외부 텍스처 파일을 포함한 베이크 결과는 아닙니다.

콘크리트 파손, 철근, 배관과 잔해의 실제 메시 디테일은 OBJ에 포함합니다. Blender의 절차적 노드로 만든 얼룩·부식·미세 범프·유리 투과·먼지 대기는 게임 MTL만으로 동일하게 재현되지 않습니다. 같은 재질 표현이 필요하면 해당 노드를 이미지 텍스처로 베이크해 게임 셰이더에 연결해야 합니다.

## 빌드와 파일 전달

Client는 캐릭터·행성의 OBJ, MTL과 이미지 파일을 실행 파일 옆 `assets/model`으로 복사합니다. Server는 지면 판정에 필요한 OBJ만 `assets/model/planet`으로 복사합니다. 프로젝트의 `assets/model/planet` 파일을 바꾼 뒤 클라이언트와 서버를 다시 빌드하면 실행 폴더에도 갱신됩니다. OBJ는 저장소의 Git LFS 규칙을 사용하므로 다른 PC에서는 `git lfs pull`로 실제 모델을 받아야 합니다.

외부 모델 라이브러리 설치 없이 Visual Studio에서 Client와 Server를 빌드합니다. 직접 명령을 사용하는 경우:

```powershell
MSBuild.exe Client/Client.vcxproj /t:Build /p:Configuration=Release /p:Platform=x64
MSBuild.exe Server/Server.vcxproj /t:Build /p:Configuration=Release /p:Platform=x64
```

`Client.exe --offline`로 서버 접속 없이 맵의 시각적 배치를 확인할 수 있습니다. 실제 실행 확인과 Blender의 이동 공간 검사는 서로 다른 검증입니다.

- 공중 파편·대기·충돌 프록시 표시 노드: **0개**

이전 검사는 모델 파일과 지면 조회 경로를 대상으로 했으며, 이번 로더 변경의 실행 결과나 실내의 체적 충돌·네트워크 플레이를 검증한 결과는 아닙니다.

OBJ 로딩 방식과 캐릭터 파일 배치는 `OBJ_MODEL.md`를 참고하세요.
